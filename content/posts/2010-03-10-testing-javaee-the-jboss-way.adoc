Recently, we have been working hard on a solution to improve the testability of link:http://in.relation.to/Bloggers/YouShouldUpgradeToJavaEE6[Java EE], and particularly link:http://www.jboss.org/jbossas/[JBoss AS]. I am pleased to say that a critical piece of the puzzle, link:http://arquillian.org[Arquillian], is now available. Congratulations to Aslak and the Arquillian team for releasing the first alpha of Arquillian!

[quote]
____
The mission of the Arquillian project is to provide a simple test harness that developers can use to produce a broad range of integration tests for their Java applications. A test case may be executed within the container, deployed alongside the code under test, or by coordinating with the container, acting as a client to the deployed code.
____

Arquillian defines two styles of container, remote and embedded. A remote container resides in a separate JVM from the test runner. Its lifecycle may be managed by Arquillian, or Arquillian may bind to a container that is already started. An embedded container resides in the same JVM and is mostly likely managed by Arquillian. Containers can be further classified by their capabilities. Examples include a fully compliant Java EE application server such as GlassFish, JBoss AS, or Embedded GlassFish; a Servlet container such as Tomcat or Jetty; and a bean container such as Weld SE. Arquillian ensures that the container used for testing is pluggable, so the developer is not locked into a proprietary testing environment.

Arquillian seeks to minimize the burden on the developer to carry out integration testing by handling all aspects of test execution, including:

* managing the lifecycle of the container (start/stop)
* bundling the test class with dependent classes and resources into a deployable archive
* enhancing the test class, including resolving `@Inject`, `@EJB`, and `@Resource` injections
* deploying the archive to test (deploy/undeploy)
* capturing results and failures

To avoid introducing unnecessary complexity into the developer's build environment, Arquillian integrates transparently with familiar testing frameworks such as JUnit 4 and TestNG 5, allowing tests to be launched using existing IDE, Ant, and Maven test plugins without add-ons.

_The Arquillian Mission Statement_

The first alpha release of Arquillian supports link:http://www.jboss.org/jbossas/[JBoss AS] (remote deployments), link:http://glassfish.dev.java.net/[GlassFish] (embedded deployments), link:https://docs.jboss.org/weld/reference/1.0.0/en-US/html/environments.html#d0e5064[Weld SE] (embedded deployments), and link:http://openejb.apache.org/[OpenEJB] (embedded deployments). You can also inject beans and components using `@Resource` or `@Inject` into test cases.

We will add supported containers in future releases. If you want to see your favorite container on the list, link:http://community.jboss.org/en/arquillian[join our community]. We also plan to add more convention over configuration, meaning you will only need to specify a single deployment and reuse it in all your test cases. Aslak has written more about future ideas in a link:/blog/2010/03/11/arquillian-1-alpha-1-released[follow-up blog entry] announcing the 1.0.0 Alpha 1 release.

We are strong believers in writing tests which actually test business logic in the environment where it will run, rather than introducing mocked objects which may behave differently. While unit testing is important, it does not ensure the correctness of two objects which interact with each other.

With the help of the link:http://jboss.org/shrinkwrap[ShrinkWrap] project, Arquillian gives you the ability to create micro-deployments around your tests. Micro-deployments are contained subsections of your application logic, giving you control over the level of integration testing.

We also know you need a convenient way to run tests quickly, which is why we are getting link:http://community.jboss.org/docs/DOC-13843[JBoss Embedded AS] in shape. Embedded AS offers the potential to bootstrap JBoss AS inside the same JVM when you run your test, making it easy to debug. Embedded AS support did not make this release, but we will push it out as soon as it is ready.

Testing your components and services gets you a long way, but you will nearly always want to test your presentation tier as well. Frameworks like link:http://www.jboss.org/jsfunit[JSFUnit] and link:http://seleniumhq.org/[Selenium] allow you to exercise the workflows your users will use. Support for both frameworks is planned, as well as support for link:http://community.jboss.org/docs/DOC-14882[Mock JSF Objects].

If you are worried that Arquillian requires build-script wizardry, let us surprise you again! Running these tests from within the IDE is a key goal of Arquillian and the key to a rapid development cycle. Arquillian requires no build wizardry. Check out the link:http://docs.jboss.org/arquillian/reference/1.0.0.Alpha1/en-US/html_single[documentation] and give it a try today.
