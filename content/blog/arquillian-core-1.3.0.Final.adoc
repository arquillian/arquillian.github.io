= Arquillian Core 1.3.0.Final Released
:sectids!:

pass:[<i class="icon-star">]pass:[</i>] *Deployment Archives using Java SPI*

Usually, you deploy into a container using pass:[<code>@Deployment</code>] annotation. But now you can implement your own strategy to generate deployable archive. For this purpose we created simplified Java SPI pass:[<code>org.jboss.arquillian.container.test.spi.client.deployment.AutomaticDeployment</code>].

The service must conform following signature:

[listing,role="prettify",subs=verbatim]
----
/**
* Method called for generating the deployment configuration.
* @param testClass of current running test.
* @return Model object that contains all the information related to deployment configuration.
*/
DeploymentConfiguration generateDeploymentScenario(TestClass testClass);
----

Moreover, you can use pass:[<code>@BeforeDeployment</code>] method annotation which allows you to modify the archive before it is deployed. The method must be pass:[<code>public static</code>] and receive as a parameter an pass:[<code>org.jboss.shrinkwrap.api.Archive</code>] which is the archive created by pass:[<code>AutomaticDeployment</code>] implementation. The method returns enriched pass:[<code>org.jboss.shrinkwrap.api.Archive</code>] based on your needs.

[listing,role="prettify",subs=verbatim]
----
@BeforeDeployment
public static Archive addDeploymentContent(Archive archive) {
    // Modify Archive
    return archive;
}
----

pass:[<i class="icon-star">]pass:[</i>] *Test Observer*

The inner communication between Arquillian Core and other Arquillian extensions is based on the event machine. To get information about the event flow you can run your tests using the property pass:[<code>-Darquillian.debug=true</code>].

In case you need to add an additional logic to the whole test suite, you can use Arquillian SPI and create your own Arquillian extension to observe any event that you need. The downside of this approach is that this extension is applied to all test classes.

In this release, we introduce a new annotation pass:[<code>@Observer</code>]. Adding it to the test class you can specify additional observers that will be applied only to this specific test class (without any need of using SPI). You can observe any Arquillian event in the context of the related test class that you need (starting with pass:[<code>BeforeClass</code>] and ending with pass:[<code>AfterClass</code>]):

[listing,role="prettify",subs=verbatim]
----
@RunWith(Arquillian.class)
@Observer(MyObserver.class)
public class MyTestCase {
----

The Arquillian observer class has to have a non-parametric constructor and the observer method should be defined by pass:[<code>@Observes</code>] annotation:

[listing,role="prettify",subs=verbatim]
----
public void observeBeforeClass(@Observes BeforeClass event) {
----
