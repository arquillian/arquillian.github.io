= Graphene 2.0.0.Alpha2 Released
:sectids!:

_Graphene 2_ is building on top of the Selenium WebDriver API and provide extensions for writing *reusable*, *robust* and *AJAX-enabled* tests with improved *readability*.

_Graphene 2_ uses the ideas from _Graphene 1_ (based on _Selenium 1 API_) and applies it to the world of http://seleniumhq.org/projects/webdriver/[Selenium WebDriver].

You can read more about the difference between Graphene 1 and Graphene 2 in the https://docs.jboss.org/author/pages/viewpage.action?pageId=53118297[Reference Documentation]

[discrete]
=== Features

[discrete]
==== Page Abstractions

https://docs.jboss.org/author/display/ARQGRA2/Page+Abstractions[Page abstractions] allow you to abstract page functionality using the well-known Selenium design pattern http://code.google.com/p/selenium/wiki/PageObjects[_Page Objects_]. In Graphene you can inject page objects directly into the test case using the pass:[<code>@Page</code>] annotation.

But we take the _Page Objects_ pattern one step further with the concept of https://docs.jboss.org/author/display/ARQGRA2/Page+Fragments[_Page Fragments_] . _Page Fragments_ are reusable parts within a page encapsulated into an object similar to _Page Objects_. A good example of _Page Fragments_ are JavaScript widgets or forms.

The concept of _Page Fragments_ comes from an idea that those components share a same underlying DOM structure, the only difference between all occurences of a component is a location in a DOM tree where a component is rendered – this is denoted by the pass:[<code>@Root</code>] annotation. You can define this root location for each concrete occurence using a pass:[<code>@FindBy(locator)</code>] annotation.

[discrete]
==== Fluent-API for Waiting Conditions

Graphene provides a set of widely used https://docs.jboss.org/author/display/ARQGRA2/Graphene+Utility+Class[conditions to avoid writing them repeatedly].

[discrete]
==== Request Guards

https://docs.jboss.org/author/display/ARQGRA2/Request+Guards[Request guards] block the Selenium test execution until a network communication caused by a given action ends. Guards support blocking on _HTTP_ and _XHR (AJAX)_ but can also be used to verify that no such requests were done.

[discrete]
==== Under the Hood

There are some low level features exposed as API that are used by Graphene internally. While not used regularly within a normal test, can be handy to write more robust tests:

[discrete]
===== https://docs.jboss.org/author/display/ARQGRA2/JavaScript+Interface[JavaScript Interface]

This allows you to write a Java interface which automatically translates Java API invocations to JavaScript calls:

[listing,role="prettify",subs=verbatim]
----
@JavaScript
public interface Document {
    String getTitle();
}
----

[discrete]
===== Page Extensions

https://docs.jboss.org/author/display/ARQGRA2/Page+Extensions[Page Extensions] allow you to inject arbitrary JavaScript code in the page under the test. The javascript code might help you to test complex situations as well as bring completely new features for improving testing. Graphene internally uses _Page Extensions_ for _Request Guards_.

[discrete]
===== https://docs.jboss.org/author/display/ARQGRA2/Graphene+Context+and+Proxy[Graphene Context]

Graphene allows you to obtain current thread-local context of a browser session and inject it exactly where you need. No more need for driver reference propagation.

[discrete]
==== Documentation

Last but definitely not the least addition is https://docs.jboss.org/author/display/ARQGRA2/Home[the great documentation] for all of the features above including answers for general questions like https://docs.jboss.org/author/pages/viewpage.action?pageId=53118297[_how Selenium 1&#44; Graphene 1&#44; Selenium WebDriver and Graphene 2 relates to each other_], what’s the https://docs.jboss.org/author/display/ARQGRA2/Using+Drone[_relation between Graphene’s&#44; Drone and Arquillian_].

[discrete]
=== https://docs.jboss.org/author/display/ARQGRA2/Getting+Started[Getting Started]

It’s the same as with any other Arquillian extension: open the IDE, setup the https://docs.jboss.org/author/display/ARQGRA2/Framework+Integration+Options[Maven dependency] and you are ready to https://docs.jboss.org/author/display/ARQGRA2/Getting+Started[start testing]!

[discrete]
=== What’s next?

In the upcoming releases, we would like to focus on more new features as well as migrate some features from Graphene 1 to Graphene 2:

* Forge plugin for quick start
* command interceptors
* parallel browser session control
* jQuery/Sizzle locators
* AJAX/HTTP Communication Halter
* page abstraction improvements
* closer integration with the Arquillian event system
* helpers for writing browser specific code
