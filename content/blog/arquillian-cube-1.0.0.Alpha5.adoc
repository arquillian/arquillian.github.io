= Arquillian Cube Extension 1.0.0.Alpha5 Released
:sectids!:

[discrete,role="highlights"]
=== What’s included in the Alpha5 release?

pass:[<i class="icon-star">]pass:[</i>] New CubeController APIs::
+
--
The pass:[<code>CubeController</code>] API got a bit of an upgrade and you can now programtically do things like copy files and check internal states.

* Copy files from Container

[listing,role="prettify",subs=verbatim]
----
void copyFileDirectoryFromContainer(String cubeId, String from, String to)
----

* See changes to the filesystem

[listing,role="prettify",subs=verbatim]
----
List<ChangeLog> changesOnFilesystem(String cubeId);
----

* Output running Container processes

[listing,role="prettify",subs=verbatim]
----
TopContainer top(String cubeId);
----

* Copy log files

[listing,role="prettify",subs=verbatim]
----
void copyLog(String cubeId, boolean follow, boolean stdout, boolean stderr, boolean timestamps, int tail, OutputStream outputStream);
----
--



pass:[<i class="icon-star">]pass:[</i>] New external configuration file::
+
--
The configuration property pass:[<code>dockerContainers</code>] or pass:[<code>dockerContainersFile</code>] can now be replaced by simply having a file on classpath called pass:[<code>cube</code>]. If the file exists and the pass:[<code>dockerContainersX</code>] configuration options are not set then this file will be read instead. The format of the content of the file is still the same.
--



pass:[<i class="icon-star">]pass:[</i>] Default await strategy changed::
+
--
The default await strategy has up until now been pass:[<code>NativeAwaitStrategy</code>] which use the pass:[<code>Docker</code>] API to see if the container has started or not. This highly depends on the container and how it’s written.

In Alpha5 the default strategy has changed to use pass:[<code>PollingAwaitStrategy</code>] with the pass:[<code>ss</code>] option. Now Cube will not determine the container started until all confiugred ports are available. The check is done from inside the container to avoid any false positives of rerouted port being opened before bound on the target container.
--
