= Arquillian Persistence Extension 1.0.0.Alpha2 Released
:sectids!:

[discrete]
=== Some of the highlights in this release

Renamed pass:[<code>@Data</code>] and pass:[<code>@Expected</code>] annotation to more meaningful pass:[<code>@UsingDataSet</code>] and pass:[<code>@ShouldMatchDataSet</code>].

pass:[<code>datasets</code>] folder is now a default location for all data set files. Files specified in pass:[<code>@UsingDataSet</code>] and pass:[<code>@ShouldMatchDataSet</code>] will be first lookup in this directory. If not found search will be performed starting from root folder.

[listing,role="prettify",subs=verbatim]
----
@Test
@UsingDataSet("users.yml")
@ShouldMatchDataSet("expected-users.yml")
public void shouldChangeUserPassword() throws Exception {
   // given
   String expectedPassword = "LexLuthor";
   UserAccount user = em.find(UserAccount.class, 2L);

   // when
   user.setPassword("LexLuthor");
   em.merge(user);

   // then
   assertThat(user.getPassword()).isEqualTo(expectedPassword);
}
----

New feature of dumping database state during test execution has been added. Following phases are covered:

* Before seed (before test execution).

* After seed (before test execution).

* Ater test.

* After clean.

This can be configured in pass:[<code>arquillian.xml</code>] as follows:

[.filename]
arquillian.xml

[listing,role="prettify",subs=verbatim]
----
<extension qualifier="persistence">
	<property name="dumpData">true</property>
</extension>
----

pass:[<code>@Transactional</code>] support can be now used standalone either on class or test method level.
