= Arquillian Core 1.0.2.Final Released
:sectids!:

Another little maintenance release in the Arquillian 1.0 series.

The pass:[<code>@Deployment</code>] can now be defined on private and protected methods. The same package and protected support is applicable to the SPI level for service and observer implementations.

[listing,role="prettify",subs=verbatim]
----
@Deployment
static JavaArchive createDeployment() {
   ...
}
----

Using environment variables in pass:[<code>arquillian.xml</code>] is now possible via the property expression pass:[<code>ENV.name</code>]

[listing,role="prettify",subs=verbatim]
----
<container qualifier="example">
   <property name="jbossHome">${ENV.JBOSS_HOME}</property>
</container>
----

Ever run into this exception? "`UnsupportedOperationException: Multiple WebArchives found in X.ear. Can not determine which to enrich.`" +
The exception happens when the pass:[<code>Servlet Protocol</code>] in Arquillian attempts to enrich an pass:[<code>EnterpriseArchive</code>] for pass:[<code>in-container</code>] testing, but multiple pass:[<code>WebArchives</code>] were found in the Deployment, and it can’t determine which you want to test. With the help of https://community.jboss.org/people/robertpanzer[Robert Panzer] this is now supported. You can give a pass:[<code>Protocol</code>] a hint to which pass:[<code>Archive</code>] is under test by using the new pass:[<code>Testable.archiveToTest(Archive)</code>] method.

[listing,role="prettify",subs=verbatim]
----
@Deployment
static EnterpriseArchive create() {
   return ShrinkWrap.create(EnterpriseArchive.class)
      .addAsModule(...some..war..)
      .addAsModule(
         Testable.archiveToTest(
            ShrinkWrap.create(WebArchive.class)
               .addXYZ(...)
         )
      );
}
----
