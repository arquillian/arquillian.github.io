[discrete,id="portlet-archive"]
=== Shrinkwrap Archive type for portlets

We can now use pass:[<code>PortletArchive</code>] instead of pass:[<code>WebArchive</code>] when we’re creating micro deployments for testing a portlet. In it includes methods for setting the content of portlet.xml without needing to specify the path, in a similar manner that pass:[<code>WebArchive</code>] provides setWebXML() methods.

[discrete,id="portlet-descriptor-helper"]
=== Helpers for creating portlet.xml

pass:[<code>PortletArchive</code>] also adds some nice helpers for creating pass:[<code>GenericPortlet</code>] or pass:[<code>GenericFacesPortlet</code>] portlet definitions within portlet.xml. A pass:[<code>GenericPortlet</code>] can be added to portlet.xml by:

[listing,role="prettify",subs=verbatim]
----
Shrinkwrap.create(PortletArchive.class)
	.createSimplePortlet(MyPortletClass.class);
----

And adding a portlet for JSF is:

[listing,role="prettify",subs=verbatim]
----
Shrinkwrap.create(PortletArchive.class)
	.createFacesPortlet("portletName", "Portlet Title", "index.xhtml");
----

For examples on how to use these extensions with their respective portal containers, you can take a look at the https://github.com/portletbridge/portletbridge/tree/master/core/impl/src/test/integration/org/jboss/portletbridge/it[testsuite] of Portlet Bridge.
