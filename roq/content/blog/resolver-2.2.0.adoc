= ShrinkWrap Resolver 2.2.0 Released
:sectids!:

// Historical interpolation #{site.project_space} = http://community.jboss.org/en/arquillian from https://arquillian.org/blog/2015/09/17/resolver-2-2-0/ (captured 2026-11-13).

The most significant change since the previous release is the postponing of the settings.xml loading. +
Previously, when a user wanted to specify completely different settings.xml:

[listing,role="prettify",subs=verbatim]
----
Maven.configureResolver().fromFile("path/to/my_settings.xml");
----

During the call pass:[<code>configureResolver()</code>] the default settings.xml was immediately loaded and later on regenerated with the given pass:[<code>my_settings.xml</code>]. This process could in some cases cause unexpected behavior (eg. the default settings.xml was corrupted).

In this new release, the loading has been postponed to the time when:

. the settings.xml is needed (eg. artifacts resolving) +
or
. the resolver is configured with some specific settings.xml (eg. calling pass:[<code>fromFile(&quot;path/to/my_settings.xml&quot;)</code>])

So, there is no change for the user in the usage – it now just does what the user wants (ie. when some different settings.xml is specified, the default one is never loaded).
