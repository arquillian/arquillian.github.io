= Smart Testing 0.0.8 Released
:sectids!:

[discrete]
=== Test method selection

In all previous versions of the Smart Testing tool, by using the pass:[<code>selecting</code>] mode, it was possible to select the whole test classes only.

In this release, we have introduced a possibility of selecting on the test method level. This new feature can be applied with two strategies: pass:[<code>failed</code>] and pass:[<code>categorized</code>]. +
In case of the pass:[<code>failed</code>] strategy – if you have a class with 10 test methods and only one of them fails, then in the next build Smart Testing selects and executes only the one test method that failed instead of running the whole test class. This should minimize the test suite execution and make the feedback loop much faster. +
In case of the pass:[<code>categorized</code>] strategy, it means that Smart Testing now resolves the annotations specified on the test methods and is able to select only test methods that belong to required categories. +
By default, it is enabled for both strategies, but you can disable it either in the configuration file or using system properties pass:[<code>-Dsmart.testing.failed.methods=false</code>] or pass:[<code>-Dsmart.testing.categorized.methods=false</code>] respectively.

[.info]
Test method selection can be used only with the pass:[<code>selecting</code>] mode.

[discrete]
=== What’s next

In the next release, we are going to provide you a support for excluding categories in the pass:[<code>categorized</code>] strategy. Stay tuned!
