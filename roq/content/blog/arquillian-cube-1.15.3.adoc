= Arquillian Cube Extension 1.15.3 Released
:sectids!:

[discrete]
=== Highlights of this release

Apart from several bug fixes, this release contains three awesome features.

[discrete]
=== Fabric8 Maven Plugin integration

From now you can use https://maven.fabric8.io/[fabric8-maven-plugin] to build images and generate k8s/openshift artifacts and let cube use it in your tests.

However you have to configure pass:[<code>fabric8-maven-plugin</code>] using pass:[<code>arquillian.xml</code>] as per your need.

Here’s an example:

[listing,role="prettify",subs=verbatim]
----
<extension qualifier="openshift">
    <property name="cube.fmp.build">true</property>
</extension>
----

By enabling this property, cube will build images, generate resources using pass:[<code>fabric8-maven-plugin</code>] when running test from pass:[<code>Maven</code>] or pass:[<code>IDE</code>].

[.info]
User can configure to run pass:[<code>fabric8-maven-plugin</code>] only from pass:[<code>IDE</code>] (not from maven build) by setting property pass:[<code>cube.fmp.build.disable.for.mvn</code>] to pass:[<code>true</code>]. Look http://arquillian.org/arquillian-cube/#_fabric8_maven_plugin_integration_with_cube[here] for more configuration options.

Look at complete example https://github.com/arquillian/arquillian-cube/tree/master/openshift/ftest-openshift-fabric8-maven-plugin[here].

[discrete]
=== Expression Resolver for @RouteUrl

To resolve expression pass:[<code>@RouteURL(&quot;${my.expression}&quot;)</code>], Arquillian Cube looks in hierarchy of system property → environment variable → properties defined in arquillian.xml.

For Example if user is using pass:[<code>@RouteURL(&quot;${route.name}&quot;)</code>] with openshift extension configuration in pass:[<code>arquillian.xml</code>] like

[listing,role="prettify",subs=verbatim]
----
  <extension qualifier="openshift">
    <property name="route.name">my-route</property>
  </extension>
----

then pass:[<code>@RouteURL(&quot;${route.name}&quot;)</code>] resolves to pass:[<code>@RouteURL(&quot;my-route&quot;)</code>]. Look at https://github.com/arquillian/arquillian-cube/tree/master/openshift/ftest-openshift-resources-standalone[ftest] for complete example.

[discrete]
=== Await Strategy – docker++_++health

Docker has https://docs.docker.com/engine/reference/builder/#healthcheck[HEALTHCHECK] instruction to test a container is still working. We have added new Await strategy pass:[<code>docker_health</code>] to wait for container to start working as per pass:[<code>HEALTHCHECK</code>] instruction defined in pass:[<code>Dockerfile</code>].

Many thanks to https://github.com/tjamet[Thibault Jamet] for providing implementation of pass:[<code>docker_health</code>] Await strategy.
