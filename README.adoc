= Arquillian Website Source
:toc:
:toc-title: What's in here?
:toclevels: 2

This repository contains the source for https://arquillian.org[arquillian.org].
The site is migrating from Awestruct to Roq; the Roq build is the supported
build and deployment path.

== Local build

The build uses Maven, the JDK configured by `pom.xml`, Roq, Qute, and AsciiDoc.
The static site is written to `target/roq`, which is ignored by Git.

[source,shell]
----
mvn -B compile test-compile
QUARKUS_ROQ_GENERATOR_BATCH=true mvn -B package quarkus:run
----

Run the development server with:

[source,shell]
----
mvn -B quarkus:dev
----

The authored source follows Roq's default directories:

* `content/` contains AsciiDoc and other authored pages.
* `data/` contains only small, committed curated fallback records.
* `public/` and `web/` contain static assets and styles.
* `templates/` contains Qute layouts and page extensions.

== Provider data and cache modes

Provider responses, normalized generated data, and repository checkouts must
remain outside tracked `data/`. The default cache is `.roq-cache`; generated
provider data is staged below `target/roq-data`. Both locations are ignored.

Normal builds use fresh cache entries and conditional revalidation. A stale
entry may be used when the provider is unavailable and the provider policy
allows stale fallback; that fallback must emit a visible warning containing the
provider URL and cache key. A live provider with no usable cache fails with its
provider URL and cache key instead of silently dropping generated data.

Use these modes when working locally:

[source,shell]
----
# Normal cached/live behavior
mvn -B package

# Bypass every usable cache entry
ROQ_REFRESH=true mvn -B package
# Equivalent Maven property
mvn -Droq.refresh=true -B package

# Never contact providers; use cache or committed fixtures only
ROQ_PROVIDER_MODE=offline mvn -B package

# Reduced preview for forks and secret-free local checks
ROQ_PROVIDER_MODE=reduced-preview mvn -B package
----

`data/curated/` is intentionally committed. It prevents historical pages from
disappearing when a retired provider can no longer reproduce old data.

== Credentials

Credentials are supplied through environment variables or GitHub Actions
secrets. Never commit tokens or provider responses. The deployment workflow
uses `GITHUB_TOKEN`, optional `ARQUILLIAN_GITHUB_TOKEN`, and `JBOSS_AUTH`.

Fork pull requests must use reduced-preview mode and have no provider secrets.
The production deployment workflow runs from `main` and may use configured
secrets and the restored provider cache.

== Deployment

`.github/workflows/deploy.yml` uses the Roq GitHub Action and deploys the
generated `target/roq` site to GitHub Pages. A manual workflow dispatch offers
the `force_refresh` input, which maps to `ROQ_REFRESH=true` for that run.

The workflow caches `.roq-cache` by branch and restores the most recent branch
cache before generation. A forced refresh still bypasses the restored cache;
the refreshed entries are available to later normal builds.

== Migration policy

Pages are ported to AsciiDoc and Qute. A page is not a production-page scrape
wrapped in a Roq template. Existing pure HTML pages may be copied and adapted
to the new CSS, while existing templated pages are converted to authored
AsciiDoc/Qute source. If Roq changes a URL, the aliases plugin provides the
redirect from the old production URL.

Deployment and final visual acceptance remain human-reviewed. Compare the
generated site with the same production URLs at desktop and mobile widths
before enabling production deployment changes.
